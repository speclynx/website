Manifesto

A note from the maintainers

Why we built SpecLynx, and what we are promising.

01

Where we come from

We maintained Swagger Editor and Swagger UI, and on the Java side Swagger Core and Swagger Codegen, for years. We contributed to the OpenAPI, Arazzo, and AsyncAPI specifications themselves. That is where we learned what API tooling looks like from the inside, and where ApiDOM was born.

02

What was broken

Our own tools worked on strings and plain JavaScript objects. Finding the line for an error meant translating a JSON Pointer back into a position. Dereferencing a $ref was done with JSON Patch, which was complicated, hard to maintain, and never quite right. And the moment a document had a syntax error the parser threw, and syntax highlighting went out of the window. That is the normal state of a document while a human is writing it.

Other parsers took a different route and forced every specification into one canonical model. Not every feature of every spec fits such a model, so things got lost in translation, and each new spec version meant reworking the model.

03

What we believe

Tooling should work on an abstract representation of the parsed document, not on strings or objects. One underlying structure shared by every specification, with the semantics of each spec layered on top rather than squeezed into a canonical model. That structure has to represent documents with recoverable syntax errors, because that is what editing looks like. Given that structure, proper traversal, dereferencing, and bundling become ordinary work instead of heroics.

04

Why our perspective is unique

We built the layer other tools are built on, and we lived with its limitations. ApiDOM started while we were still there. SpecLynx is what we could do with it once we left: the work we knew was needed, and never found the time for.

05

What SpecLynx is, and is not

SpecLynx is ApiDOM and the tools we build on it: the Language Service, the CLI, the browser Editor, and the VS Code extension. All of it is open source under Apache 2.0, runs on your machine, and needs no account. It is not a hosted platform, and we are not building one.

06

Where we are going

We commit to three things. Everything our tools run on is published to npm under Apache 2.0. The packages that power the CLI and the Editor are the same ones you install, with nothing held back. Keeping up with the specifications as they ship new versions, as we did for OpenAPI 3.1, Arazzo 1.1, and Overlay 1.1. And keeping the foundation open and local-first. We do not promise dates.

If you write specs, run the CLI on your own document. If you build tooling, build it on ApiDOM and tell us what is missing.

Vladimír Gorej and Francesco Tumanischvili Maintainers, SpecLynx
